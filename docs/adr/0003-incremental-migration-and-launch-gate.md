# 数据分批迁移，发布只要求三条门槛

按 ADR-0001 统一数据形状，约 20 个数据文件不一次性迁完。先以超市（字段最接近目标形状）做试点，跑通 schema、构建校验和前端适配层，再按 亲子 → 活动 → 其余 Place → Tool 的顺序迁移；每迁一块，旧的并列字段和反查表随之删除。

正式发布不要求全部迁完，只要求：(1) 所有 Record 都有 Verification date 和至少一个 Source；(2) Suburb / Town 通过名单校验；(3) 已迁移的板块不再有并列字段。读者看不到数据形状，剩余板块可在发布后继续迁移。

## Consequences

- 发布后一段时间内，新旧两种数据形状并存，前端适配层必须保留到最后一个板块迁完。
- 适配层删除的时间点即迁移完成的标志。
